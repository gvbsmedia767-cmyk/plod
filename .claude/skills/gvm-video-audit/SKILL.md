# GVM Video Audit → Style → Treatment → Execution

Цель: из сырого или смонтированного видео получить проверенный план и рабочий черновик в стиле из `gvm-creative-os/style-library/STYLES.md`.

## 1. Доступ к файлу
- Путь на ПК (E:\…): GVM Connect `directory_list` → `process_start` (python/ffmpeg на ПК). Рабочая папка: `E:\Для chat\gvm_audit_<имя>` — исходники только читать, ничего не перезаписывать.
- Передача файлов ПК → облако: на ПК закодировать в base64 `.txt` (≤8 МБ на файл; больше — делить), прочитать `file_read` (результат автоматически сохраняется в tool-results), декодировать в облаке. Не читать параллельно больше 3 файлов — таймаут 60 с.
- Клиентские материалы не класть в публичный репозиторий; рабочие файлы — в scratchpad.

## 2. Технический аудит
`ffprobe` (кодек, размер, fps, битность), контакт-лист 4×4, `ebur128` (интеграл, LRA, пик), `silencedetect`. Отметь: один план/мультикамера, запас по разрешению для вертикали и наездов, звук (норма соцсетей ≈ −14 LUFS), видимые дефекты (петличка, фон, свет).

## 3. Транскрипт
`faster-whisper medium`, язык ru, `word_timestamps=True` (аудио передавать numpy-массивом через ffmpeg — у установленного PyAV нет `metadata_errors`). Существующий транскрипт рядом с файлом сверяй: он может быть от другого ролика. Ошибки распознавания имён/топонимов помечай [гипотеза], в титры не выводи без подтверждения.

## 4. Аудит содержания
Цель, аудитория, платформа; хук первых 3 с; сильные фразы с таймкодами; рабочие реплики/дубли, которые надо вырезать; незаконченные фразы (проверяй тишину и пере-распознавай короткие куски); риски (персональные данные, медицинские/религиозные формулировки — нейтрально и точно).

## 5. Выбор стиля
По таблице «Быстрый выбор» и карточкам: основной стиль + акцент, обоснование одним абзацем со ссылкой на референсы (Р/С). Если стиль «нужен шаблон» — предложи ближайший готовый и отметь, что делать.

## 6. План (treatment)
Для каждого формата: EDL с таймкодами исходника, порядок (хук → суть → доказательства → призыв), кадрирование (9:16 из 4K, наезды 1.0–1.25 на склейках), графика по времени слов, музыка (−17…−20 дБ под голос, ducking), финальная карточка и что нужно от клиента (телефон, написание имён).

## 7. Исполнение
1. На ПК: вырезать фрагменты сразу в 1080×1920 (`crop` из 4K, `-crf 24`), передать в облако.
2. `timeline.json` из слов (смещения по фрагментам, исправления ASR).
3. Job для `motion-kit/compose.js` (пример: шаблон `album-overlay`), `--preview`, проверить 6 ключевых кадров через Read и LUFS, затем финал.
4. Отдать `<имя>_mobile.mp4` в чат, мастер и путь; перечислить открытые вопросы.

## Приёмка
Нет обрезанных слов на склейках; субтитры совпадают с речью; текст не закрывает лицо; −14 ±1 LUFS, пик ≤ −1 dBFS; финальная карточка без выдуманных данных (плейсхолдер вместо неизвестного телефона).
